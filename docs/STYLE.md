# Writing style for this repo

The owner asked that nothing reads like AI text. Applies to code comments,
docs, commit messages, UI copy.

- Short plain sentences. Say the thing once.
- Comments only where the code can't say it: a reason, a gotcha, a link.
  No comment that repeats the line below it.
- No filler words: robust, seamless, leverage, delve, comprehensive,
  powerful, elegant, cutting-edge, "it's worth noting", "in summary".
- No emojis. Few em dashes. No marketing tone in the README.
- Commit messages: `type: what changed`, lowercase, body only if the why is
  not obvious. No co-author lines.
